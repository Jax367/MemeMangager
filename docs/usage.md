# 拾趣 · MemeManager

Windows 原生表情收藏夹。WPF + 系统自带 .NET Framework 4.8，无 WebView、Electron 或数据库服务。程序体积与运行内存是不同指标，内存实测见 [性能记录](performance.md)。

## 使用

运行新版 `dist/non-c/MemeManager.exe`。更新前先从托盘退出旧版（只关闭窗口不会退出），避免单实例机制重新唤起旧程序。Windows 10/11 通常已包含所需运行环境。

管理窗口采用顶部工具栏、窄侧栏与紧凑图片网格，默认「港湾雾蓝」配色参考雾灰、灰蓝与炭黑。旧版未自定义的默认外观会升级；已有自定义配色会保留，可在偏好中选择新主题。

快捷选择与管理设置分开：

- 快捷键或双击托盘：仅打开独立的小型表情选择器，支持名称搜索、分组、喜欢、最近使用、GIF 悬停预览，按使用频率排列。点击复制或按 Enter 复制当前列表第一张后，仅收起选择器；Esc 或再次按快捷键也仅收起选择器。
- 托盘「表情管理」或选择器底部的管理按钮：打开完整资料库，执行导入、分组、重命名等管理操作。
- 托盘「外观与偏好」：直接打开独立设置窗口，无需先显示管理窗口。设置窗口不阻塞选择器或管理窗口，可同时使用，重复打开会激活已有实例。
- 管理窗口左下角或托盘「图片预处理」：按需打开独立 FFmpeg 批处理工具，详情见下方。

选择器首次使用时才创建，使用与管理窗口共享的资料库、主题与缩略图缓存；卡片按视口创建，隐藏后释放图片引用。

- 添加表情：选择多张图片，拖入图片 / 文件夹，或批量导入文件夹（包括子文件夹，跳过目录链接）。按 SHA-256 去重，保留原始 GIF。
- 文件夹自动分组：点击「导入文件夹」右侧连体下拉箭头，可开启「按子文件夹名称自动分组」（默认关闭并记忆选择）。开启后，从当前目标分组开始还原子目录层级；未选分组时从顶层创建。同一父级的同名组复用，不同父级的同名目录分别建组；根目录图片加入当前分组。空目录和只有损坏文件的目录不建组。重复图片复用已有记录，并加入对应分组，同一张图片可以出现在多个目录对应的分组中。取消时保留已完成部分。
- 从剪贴板添加：点击管理页「从剪贴板添加」可直接导入；管理窗口或快捷选择器获得焦点时按 `Ctrl + V`，会先弹出预览确认框，显示数量和目标分组，确认后才添加，取消会清理临时副本。纯文本照常粘贴，不解析网址下载图片。快捷选择器使用自己当前选择的分组。支持多张图片文件、原 GIF / PNG 数据和截图位图，位图保存为 PNG；动图效果取决于剪贴板是否提供原文件或 GIF 数据。原内容不修改，重复图片复用并加入目标分组。只在点击或按键时读取，没有后台监听；临时文件在非 C 盘资料库 `temp` 中，结束后清理。内嵌图片限制 50 MB，位图限制 1 亿像素。
- 分组与子分组：侧栏 `＋` 新建顶层组，右键分组选择「新建子分组」，也可用「移动分组到」调整父级。父组可展开 / 收起，选中父组会汇总所有后代，图片不会重复计数。删除单个组会将子组上移一级，并保留图片与其它归属。右键图片打开「所属分组（可多选）」逐项勾选，一张图片可以属于多个分组，磁盘仍只保留一份原文件；「清空所有分组归属」可设为未分组。旧版单分组资料库自动兼容。
- 批量分组：点击「批量分组」勾选图片，或全选当前结果，选择目标组后点「加入分组」。加入时保留其它分组，搜索和滚动保留勾选；选择「清空分组（未分组）」会清空全部归属。选择模式下点击只勾选，不复制。也可先选侧栏分组，再多选文件、拖放或导入文件夹。
- 窗口置顶：管理页右上角「置顶」与选择器底部「置顶」分别控制两个窗口，各自保存并在重启后沿用。置顶只改变窗口层次，点击复制后仍会按原来的规则自动收起。
- 搜索与排序：名称搜索；使用最多、最近添加、最近使用、名称排序。
- 相似查重：左下角或托盘「相似表情查重」手动开始检测。建议清理优先选未分组副本，保留项优先已有分组，再比较使用次数与分辨率；默认不勾选，人工确认后删除，每组至少留一张。被删除图片的分组归属会合并到保留图，支持撤销。详见 [查重手册](duplicates.md)。
- 点击图片：复制原文件和静态图片兼容格式到剪贴板，记录使用次数，随后隐藏窗口。在聊天窗口按 `Ctrl + V` 粘贴。支持文件粘贴的应用可接收原始 GIF；只接收位图的应用会得到静态首帧。程序不模拟向其他软件发送按键。
- GIF 缩略图静态展示，悬停播放，离开即停，避免同时解码大量动图。
- 默认 `Ctrl + Shift + Space` 呼出 / 收起选择器；`Esc` 收起当前选择器或管理窗口。右键托盘图标可分别选择表情、管理、设置或彻底退出。关闭选择器或管理窗口会保留托盘进程。
- 外观与偏好：四款主题、任意 HEX 强调色，背景 / 卡片 / 文字 / 侧栏独立配色、卡片尺寸、圆角、自定义全局快捷键、登录 Windows 自启。快捷键冲突会提示。
- 自定义背景：在「外观与偏好 → 背景图片」选择本地图片，调节背景可见度，点击「保存偏好」应用到管理窗口与快捷选择器。「清除」或「恢复默认」后保存可移除背景。图片等比铺满，GIF 使用静态首帧；WebP 需要系统解码器支持。单文件限制 50 MB、1 亿像素，导入后最长边缩至不超过 1600 像素，保存到非 C 盘资料库的 `backgrounds`，不会修改原图。原图移动或删除不影响已保存背景；两个窗口均收起时释放背景图片引用，下次打开按需加载。清除设置会保留磁盘副本，便于资料库备份恢复。
- 格式：GIF、PNG、JPEG、BMP、TIFF；WebP 依赖系统 WIC 解码器，无法解码的文件会计入失败数量。

## 图片预处理

入口为管理窗口左下角「图片预处理」按钮，也可从托盘同名菜单打开。工具在单独的 `MemePreprocessor.exe` 进程中运行；主程序没有对该模块的程序集依赖，平时不创建其窗口、文件队列或处理进程。关闭预处理窗口后进程退出。如果正在处理，关闭会先取消 FFmpeg、清理当前临时文件再退出。

1. 添加多张图片、文件夹，或拖入文件。可选包含子文件夹。队列只保存文件路径，不加载缩略图。
2. 默认将其它格式转为 GIF，并开启「保留动图」：静态图片生成单帧 GIF，动态 WebP / APNG 保留各帧和播放间隔；原有 GIF 原样复制到输出目录，也可随结果一键导入，不会重新编码或调整原 GIF 的尺寸。也可选择 PNG / APNG、JPEG、无损 WebP、BMP，或保持原格式；取消「统一尺寸」可仅转换格式。
3. 需要统一规格时填写宽高（1–4096 像素），选择等比留边、居中裁切或拉伸。PNG / WebP 保留透明，JPEG / BMP 自动合成白底。
4. 选择输出目录，点击「开始批处理」。默认输出到非 C 盘资料库的 `processed/时间戳` 子目录，C 盘输出目录会被拒绝。输出不覆盖输入或已有同名文件，冲突自动编号，不会自动替换收藏库中的图片。
5. 完成后选择目标分组（默认「未分组」），点击底部「一键导入收藏库」。仅提交本次成功生成的图片；若任务已取消，也可导入已完成部分。重复图片复用已有记录并加入目标分组，返回新增、复用和失败数量，并刷新 Manager 和选择器。

一键导入通过请求队列交由 Manager 写入资料库，预处理工具不直接修改资料库 JSON。主程序未运行时会自动后台启动；如果 Manager 正在进行另一批导入，请求会等待该批结束后处理。请求保存在资料库的 `import-requests` 子目录，主程序重启后会继续处理尚未完成的请求；重试按内容去重。关闭预处理窗口不会回滚已提交的导入。

动画检测仅读取文件头与控制块，不预加载各帧。开启保留时，GIF / WebP / PNG（APNG）输出保留动画；JPEG / BMP 等静态目标会跳过动态输入并记录原因，避免静默丢失帧。取消保留勾选后，动态输入仅转换首帧，原有 GIF 跳过。原 GIF 按扩展名和文件头双重识别；开启保留时按原始字节复制，保留原来的循环、帧与透明信息。

重新编码的动画 GIF 默认循环播放，使用逐帧调色板，最多 256 色，透明度依 GIF 规范转换为透明或不透明；播放间隔按 GIF 的 10 毫秒精度表示，保留输入的变帧间隔及最后一帧停留时间。静态图不会自动生成新的动画效果。需使用支持动画 WebP 解码的 FFmpeg 版本，本机 FFmpeg 9.0.2 已验证。

每次仅运行一个 FFmpeg 进程，限制处理线程，单文件超时 3 分钟。可随时取消，已完成的输出保留，正在处理的临时结果删除。输出目录包含 CSV 处理记录，列出成功、原样保留、跳过及失败原因。

FFmpeg 仅在点击开始后启动，单张处理完成即结束，没有后台守护进程。不会随主程序启动或呼出表情选择器而运行。工具窗口打开但未开始处理时仍会有窗口进程本身的内存；完全不用时关闭工具即可释放整个进程。

不捆绑 FFmpeg。工具自动查找程序目录、`tools` 子目录和 `PATH` 下的 `ffmpeg.exe`，也可通过「FFmpeg」按钮指定。选择的路径存于资料库目录的 `ffmpeg-path.txt`，下次打开沿用。本机已安装的 FFmpeg 可直接使用。

## 数据与隐私

构建后，资料库默认位于项目根目录的 `data`，请将项目放在非 C 盘。发行目录中的 `storage-path.txt` 指定实际资料库；主程序和预处理工具共用它，升级版本时不会新建另一份资料库。图片位于 `images`，分组、使用次数、偏好在 `library.json`，缩略图在 `thumbnails`，预处理输出在 `processed`，导入请求在 `import-requests`，临时文件在 `temp`。

程序启动时仅修改自身进程的 `TEMP` / `TMP` / `TMPDIR`，指向资料库 `temp`，并由子进程继承。FFmpeg 还会将工作目录和临时目录设到输出目录的 `.work`。构建临时文件使用项目的 `.build-temp`。不会修改 Windows 全局环境变量。Windows 自身管理的注册表、字体缓存及运行时文件仍由系统管理。

保存采用临时文件 + 原子替换，同时保留 `library.json.bak`。主资料库损坏时尝试恢复备份；两份都损坏时停止启动，保护文件。备份或迁移请退出程序后复制整个资料库文件夹。

可指定独立资料库：`MemeManager.exe --data-dir "D:\MyMemes"`，也可修改发行目录的 `storage-path.txt`（支持绝对路径或相对发行目录的路径）。C 盘资料库会被拒绝，不再回退到 AppData。没有路径文件时优先采用程序旁的 `data`；程序位于 C 盘时寻找可用的非 C 固定磁盘。设置开机自启时会保存当前非 C 盘资料库参数，并在新版启动时尝试更新旧自启项。

旧版 AppData 资料库迁移脚本为 `scripts/Move-DataOffC.ps1`：先复制到项目 `data`，按 SHA-256 校验每个文件及表情完整性；`-Finalize` 再将原资料库移动到项目 `data-migration-backup`，并再次校验。脚本会检查固定源路径、目标范围和程序互斥锁，目标已存在时不会覆盖。历史程序仍使用旧路径，请退出旧版后只运行新版。

## 构建与验证

在项目目录执行 PowerShell：

```powershell
.\build.ps1
.\test.ps1
.\test-preprocess.ps1
```

编译使用 Windows 自带的 .NET Framework C# 编译器，无需下载 NuGet 包或安装 .NET SDK。编译产物在 `dist/non-c`，包含 `MemeManager.exe`、独立的 `MemePreprocessor.exe`、两个配置文件以及 `storage-path.txt`，请保留整个目录。也提供两个对应的传统 .NET Framework 项目文件；构建 `MemePreprocessor.csproj` 时会引用主程序项目。

自动检查涵盖导入、去重、取消、损坏文件、动图保留与播放、数据持久化、备份恢复、界面渲染、搜索、频率排序与主题切换，并输出浅色 / 深色界面 PNG。不会更改实际剪贴板或注册开机启动；全局快捷键注册和开机启动需在正常 Windows 桌面环境中验证。

新增检查覆盖后台启动不解码图片、2000 张记录下的卡片数量限制、滚动到末尾、隐藏时释放图片引用。缩略图缓存位于资料库的 `thumbnails` 文件夹，可在退出程序后删除，程序会按需重建。完整的 GIF 原文件仍在 `images`。

`test-preprocess.ps1` 使用本机真实 FFmpeg，检查 GIF / PNG / JPEG / WebP / BMP 转换、动态 WebP 和 APNG 的帧数 / 画布 / 颜色变化 / 播放间隔、不等帧时长与末帧停留、原 GIF 逐字节保留、静态目标保护、透明与白底、三种统一尺寸模式、原文件保护、中文与特殊字符路径、失败记录、递归、取消及临时文件清理、FFmpeg 退出、工具窗口生命周期。主程序测试另外覆盖预处理结果导入、分组持久化、缺失文件、重试去重及请求完成清理。这些测试不读写个人图库。可用 `-FfmpegPath` 指定测试用 FFmpeg。

性能基准：将旧版程序及配置放在 `.test-data/baseline` 后运行 `.\benchmark.ps1`，脚本会生成独立样本、分别启动两个版本并输出 CSV，不使用你的个人资料库。
