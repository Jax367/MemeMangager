# 相似表情查重

从管理窗口左下角或托盘菜单选择「相似表情查重」，点击「开始检测」。打开窗口本身不会扫描；没有定时任务、后台监听或常驻特征缓存。检测可以取消，关闭窗口也会取消。

## 人工确认与清理

- 默认选择「严格」模式。需要扩大范围时切换「标准」并重新检测。
- 结果按相似组展示，默认不勾选任何图片。勾选框始终表示「选择删除」；「建议保留」标记显示在图片上方。
- 「选择建议删除项」会勾选每组建议保留图片以外的项，再点击「删除勾选」并确认即可清理。也可以自己勾选；每个相似组至少要留一张。
- 「一键清理重复项」直接提出同样的清理方案，确认后执行。建议清理优先选择未分组副本，保留项依次优先已有分组、使用次数、分辨率、较早的添加时间。
- GIF 悬停可播放，便于核对动作。相似图片可能含不同文字、表情或细节，请检查预览再决定。
- 清理时会把被删除副本的所有分组归属合并到保留图上，保留一份文件即可继续出现在多个分组。撤销会恢复原图及其父子分组，并撤销本次合并产生的归属；保留之后另加的其它分组。
- 删除只处理收藏库副本，原先导入的外部文件不会修改。导入正在进行时，清理与撤销会等待用户稍后重试。

清理后的文件和元数据保存到非 C 盘资料库的 `duplicate-trash/批次`，包括图片原文件和 `manifest.json`。点击「撤销上次删除」可恢复，重新打开工具后也能发现最近的可恢复批次。确认不需要恢复后，可手动删除对应回收目录释放磁盘空间。保存失败时会回滚图片移动和资料库更改。

## 检测方式与范围

项目内的 C# 实现使用 32×32 图像的 DCT 感知哈希，结合差分哈希、平均颜色和宽高比筛选候选；用汉明距离比较特征，BK-tree 缩小候选查找范围。严格 / 标准模式的感知哈希阈值分别为 4 / 8。同组成员都需要与建议保留项匹配，避免通过一连串弱相似关系合并大量不同图片。算法概念参考 [pHash 的设计说明](https://www.phash.org/docs/design.html)。

GIF 还要求帧数、总时长接近，并比较首帧、中间帧和最后一帧。抽样不能证明整段动画完全相同，仍需人工预览；不会仅凭首帧将不同帧数的动图与静态图归成一组。

为保护未完整比较的内容，动态 PNG / WebP、多页 TIFF、超过 2000 帧的 GIF 和超过 1 亿像素的图片不参与近似查重；无法解码的文件也会计入跳过数量。静态 WebP 依赖系统 WIC 解码器。检测不会修改这些原文件。

图片逐个读取、释放，结果页每页最多创建 24 张预览；关闭窗口后释放预览和结果。原图解码仍可能有临时内存开销，尤其是高分辨率图片和 GIF。不会启动 FFmpeg 或引入新的运行库。

本功能筛选的是视觉相似候选，不能替代人工判定。导入时的 SHA-256 去重仍独立工作，用于复用字节完全相同的文件，并关联到目标分组。
