# 内存对比 · 2026-10-15

同一台 Windows 机器、独立测试进程、同一资料库：200 张 768×512 PNG，加 12 张 640×480、8 帧 GIF。测试不是用户的真实资料库，也不是对任务管理器截图的精确复现。

| 阶段 | 旧版工作集 MiB | 新版工作集 MiB | 旧版专用字节 MiB | 新版专用字节 MiB |
| --- | ---: | ---: | ---: | ---: |
| 后台启动 | 168.5 | 68.9 | 149.0 | 59.6 |
| 首次打开 | 208.4 | 91.5 | 184.0 | 68.2 |
| 滚动浏览后 | 373.9 | 109.9 | 346.5 | 89.8 |
| 收起 3 秒后 | 373.8 | 98.1 | 346.0 | 78.1 |
| 再次打开并收起 | 385.2 | 96.6 | 353.9 | 72.7 |

指标来自 `Process.WorkingSet64` 与 `PrivateMemorySize64`。工作集含共享页，专用字节包含尚未驻留的已提交内存；两者都不等同于任务管理器所有视图下的默认「内存」列。MiB = 1,048,576 字节。

新版滚动后的实际图片卡片为 22 张，加 1 个占位元素；旧版累计保留 212 张。两版可见图片均无缩略图加载失败。收起后新版图片引用与卡片清空，旧版仍保留全部卡片。

改动：

- 根据视口创建卡片，用占位区域保持滚动范围，避免越滚越多。
- 原图生成最长边 192 像素的独立 PNG 缩略图；界面不长期持有原 GIF 解码器。
- 内存缩略图缓存限制为 48 项；隐藏窗口时清空图片和卡片，停止动画，并延迟进行一次后台垃圾回收。
- 后台启动不解码缩略图。
- 对这个小型图片面板采用 WPF 软件渲染，减少图形设备开销。
- 托盘、目录选择和颜色选择使用 Win32 / Shell 接口，移除 Windows Forms 依赖。

未通过清空进程工作集等接口制造低读数。首次生成磁盘缩略图会有解码与写盘成本，实际内存随图片尺寸、GIF 帧数、DPI、桌面环境和使用步骤变化。WPF 自身仍有明显基础开销，这一版不承诺几十 MiB 以下常驻。

复测方法：保留旧版程序与配置在 `.test-data/baseline`，构建新版后执行 `benchmark.ps1`。脚本使用独立样本目录，输出 `.test-data/memory-baseline.csv` 与 `.test-data/memory-compact.csv`。首次运行还会生成样本和缩略图，缓存状态也可能影响峰值。
